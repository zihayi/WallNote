# 性能测量

## v0.10.2：桌面图标反馈

在同一台 Windows 11 双屏机器上运行两版 x64 打包程序，使用次屏上的独立文件抽屉，每种窗口状态交替点选两个测试文件 4 次。记录系统鼠标移入/按下至渲染器收到对应状态变化后的第一帧。测试故意将按键保持约 120 ms，以区分按下选中和松开选中。

| 未置顶抽屉（四次中位数） | v0.10.1 | v0.10.2 |
| --- | ---: | ---: |
| 移入图标至悬停反馈帧 | 149 ms | 5 ms |
| 按下鼠标至选中反馈帧 | 156 ms | 8 ms |

新版在置顶和未置顶状态下的 8 次选中均早于松键。桌面图标层覆盖工作区时，Windows 直接分发鼠标消息；不可用时回退到 WorkerW。测量记录是软件侧帧回调，不代表显示器端到端延迟。

默认右键直接打开 Windows 文件菜单。另外一组测试中，每次先把指针停在目标上 1 秒，再从右键事件计时到原生菜单可见：第一个文本文件为 136 ms，随后交替点开文本文件为 14–22 ms。停留时间不计入这些数字；刚移入便右键、剪贴板变化或 Shell 扩展冷启动时可能需要更久。快速扫过图标不会逐项构建菜单。

复测：`node scripts/smoke-drawer-mouse.mjs --packaged --physical --feedback --windows-menu`；系统菜单使用 `--packaged --windows-menu --timing --settled --check-idle`，去掉 `--settled` 可测立即点击。结果写入 `test-results/`。

## v0.10.1：Windows 文件菜单

这次计时从点击抽屉里的「Windows 文件菜单」开始，到独立探针观察到属于测试进程的前台 Win32 弹出菜单（`#32768`）可见为止。不包含用户浏览快捷菜单的时间，也不把菜单关闭或命令执行完毕当成弹出时间。

同机 Windows 11、两个 x64 打包构建，使用隔离抽屉中的本地 `.txt` 文件，显示快捷菜单后立即选择 Windows 菜单：

| 场景 | v0.10.0 | v0.10.1 |
| --- | ---: | ---: |
| 首次打开（各一次） | 1377 ms | 1588 ms |
| 接下来四次（交替选两个文本文件） | 867–963 ms | 193–221 ms |
| 四次的中位数 | 884 ms | 209 ms |

首次并没有稳定提速：新版此次构建系统命令列表用去 1446 ms，解析文件和绑定处理程序合计 30 ms。速度随文件类型、Shell 扩展及其加载状态而变。右键时后台只准备这次手势对应的文件，取消即丢弃；文件信息、窗口、扩展模式、剪贴板变化或准备结果过期时会重新构建。空闲进程保留 15 秒，实测连续操作复用同一 PID，随后自动退出。

复测：`node scripts/smoke-drawer-mouse.mjs --packaged --timing --cold-quick --check-idle`。可设 `WALLNOTE_MENU_TRACE=1` 查看原生阶段耗时（不记录路径或菜单内容）；`WALLNOTE_TEST_INSTALLED_EXE` 可指定对照版本。结果在 `test-results/native-menu-<版本>-packaged-cold-quick.json`。

## v0.10.0

Windows 11 x64，本机双屏、默认四个模块、相同初始数据，管理面板未创建。开发目录运行生产构建，桌面就绪后空闲 6 秒，使用 `scripts/measure-memory.mjs` 采样整个应用进程树。不启动 Wi-Fi 接收服务。

| 指标 | 本次修改前 | 修改后两次采样 |
| --- | ---: | ---: |
| 共享桌面渲染进程 | 1 | 1 |
| 私有提交内存 | 239.6 MB | 211.6 / 206.1 MB |
| 工作集加总（共享页会重复计算） | 725.0 MB | 702.0 / 694.5 MB |

另测打包版，开启内置 Wi-Fi 接收服务（回环网络），私有提交内存 **238.0 MB**。结果见 `test-results/memory-module-{before,after,final,wifi}.json`。不同壁纸、分辨率、进程启动时机和用户内容都会影响采样。

- 壁纸窗口只显示一张图片和吸附线，不挂载 React。工作台和桌面共用按需加载的模块入口；写便签或勾待办时，不向无关窗口重复发送数据。
- 壁纸库使用 480 × 270 缩略图，预览或应用时才读原图。内置壁纸的模糊图在构建时生成，不在首次启动时解码整张壁纸做模糊。
- 鼠标服务由消息唤醒，移除了每 15 ms 检查命令的定时器。桌面健康检查复用该服务；双屏四模块时，每轮不再启动 6 个短命进程。文件列表滚动也不再逐项测量和上报热区。
- `node scripts/smoke-drawer-mouse.mjs --physical` 在独立测试抽屉中测量右键松开至快捷菜单首次渲染帧的时间。本机一次测得嵌入 7 ms、置顶 6 ms；加 `--packaged` 测试最终打包版，分别为 17 ms、4 ms。这是软件侧计时，不是显示器端到端延迟，也不包含用户主动打开的 Windows 扩展菜单。

## 早期版本

Windows 11，双屏、四个桌面组件，同一组示例数据启动后空闲测量。下表记录 v0.5.0 的渲染优化。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 常驻渲染进程 | 7 | 1 |
| 私有提交内存 | 665.5 MB | 234.4 MB |
| 进程工作集加总 | 1225.6 MB | 737.8 MB |

私有提交内存减少约 **65%**。工作集加总包含重复计算的共享页，不等于整台电脑实际多用的物理内存。保留管理窗口时，优化版私有提交内存约为 275.5 MB。

打包版复测：1 个渲染进程，私有提交内存 236.6 MB；对应进程工作集加总 584.9 MB。

v0.6.0 启用内置 Wi-Fi 接收服务的打包版复测：1 个渲染进程，**私有提交内存 263.0 MB**，进程工作集加总 638.2 MB。这个数字包含随应用启动的接收服务及其启动进程，使用隔离数据和回环发现网络，不含真实手机日历。

主要调整：

- 桌面组件复用同站点渲染进程和图片缓存，保留沙箱及上下文隔离。
- 模糊壁纸预先生成小尺寸缓存，桌面组件不再实时模糊整屏图像。
- 静态桌面默认使用软件合成，减少图形进程的大型缓存。
- 管理窗口按需创建；关闭后空闲 30 秒自动释放。有未保存表单时保留。
- 按组件发送状态。背景不接收日程正文，时间表只接收所选日期，日历的其他日期只接收轻量记录。

实际占用会随壁纸、日程数量、打开窗口和驱动变化。可复测：

```powershell
npm run build
node scripts/measure-memory.mjs current
node scripts/measure-memory.mjs release --packaged
node scripts/smoke-memory.mjs

# 包含内置 Wi-Fi 接收服务（隔离数据、回环网络）
$env:WALLNOTE_ENABLE_WIFI_RECEIVER = '1'
$env:WALLNOTE_WIFI_TEST_LOOPBACK = '1'
node scripts/measure-memory.mjs wifi-release --packaged
```

测量结果按标签写入 `test-results/memory-<标签>.json`。测试使用独立数据目录，不读取真实日历。

若特定显卡环境的软件合成有显示问题，可在退出应用后设置 `WALLNOTE_HARDWARE_RENDERING=1` 再启动，以恢复硬件合成。
