# 桌面便签操作

## 已确认的需求

- 便签卡片可以选择背景色、新建、删除，并通过标题进入其他便签。
- 标题列表显示全部便签，包括尚未加入桌面的便签。
- 背景色提供现有五种预设及自定义颜色，自动保存。
- 后续补充：便签支持粘贴、插入、复制图片；置顶模块移动和缩放不得覆盖原桌面布局；完成验证后上传 GitHub。

## 方案

直接扩展已有便签卡片与管理面板编辑器。标题下拉列表替代仅按顺序切换的箭头；卡片标题栏增加新建、删除按钮；删除在卡片内部确认。选择原来未显示的便签时，将其加入桌面并设为当前便签。新建后直接进入新便签；删除当前便签后显示下一张，全部删除后显示新建入口。

保留仅列桌面便签的实现会无法访问其他标题，用户已明确选择全部便签。独立便签管理窗口需要多一次打开操作，因此沿用当前卡片。

## 实现约束

- 沿用 React、现有 action/reducer 与 Electron IPC；便签可选背景色字段兼容旧数据，不扩展日程颜色类型。
- 所有便签标题向便签组件提供，只有当前便签正文随桌面视图传输。
- 切换、新建、收起前等待当前保存并处理失败；保存失败时保留当前编辑内容。
- 自定义深色背景使用可读的文字颜色，预设颜色在关闭毛玻璃时也应生效。
- 图片作为可移除的正文附件显示，导入时压缩到最长边 1600 像素，随便签及 JSON 备份持久保存；保留普通文本复制粘贴。每张便签最多 8 张图片，压缩数据最多 8 MiB。
- `floatingFrames` 单独保存置顶几何信息，`dockFrames` 保存桌面布局；取消置顶回到桌面布局，再次置顶恢复独立的浮动位置。

## 实施与验证

1. 扩展便签数据校验、选择与删除逻辑，以及桌面组件操作范围。
2. 增加标题选择、新建删除及颜色盘，连接到现有保存流程。
3. 检查全部标题与正文加载、失败重试、颜色持久化、删除最后一张、管理面板与桌面窗口行为；运行类型检查、相关单元测试及界面验收。
